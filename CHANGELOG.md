# Изменения Bilem Agent

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/). Раздел версии — заметки к релизу на GitHub.

## [0.3.0-beta.13] — 2026-10-20

- **Понятный поиск 1С при подключении базы.** Вместо «Платформа 1С:Предприятие 8.3 не найдена» агент пишет, какую 1С нашёл и почему она не подходит: учебная версия (в ней нет COM-соединения), платформа без COM-коннектора (что отметить при установке), не 8.3. Ничего не нашёл — пишет, где искал.
- 1С, установленная «для текущего пользователя» (в профиле), теперь находится и подходит: веб-серверу выдаётся чтение папки этой версии 1С.
- В журнале подключения, в «Докторе» и в «Системной информации» — все найденные установки 1С: версия, разрядность, полная или учебная, COM-коннектор, модули веб-сервера. Пути в профиле — без имени пользователя.
- Тест пароля настроек больше не падает изредка из-за параллельных тестов.

## [0.3.0-beta.12] — 2026-10-20

- **Живучая публикация: если IIS не работает с модулем 1С — агент сам поднимает свой Apache.** Признак — падение IIS (сбой w3wp, пустой ответ или обрыв на проверке OData, 503 «пул остановлен»), а также IIS, который не включается. Тогда агент убирает свою публикацию IIS, публикует базу на своём Apache и проверяет заново — до зелёной проверки, ни о чём не спрашивая. Неверный пароль, права или лицензия 1С — не повод для перехода: агент пишет причину и что делать.
- **Свой Apache «Bilem Apache»:** служба `BilemApache` под виртуальной учётной записью (только свои папки), автозапуск, только 127.0.0.1 (порт от 18080, занят — следующий), вход в публикации — только с этого компьютера. Apache 2.4 и Visual C++ — внутри установщика, из интернета при настройке ничего не скачивается. Разрядность Apache — по платформе 1С (64 или 32 бита). Перед применением конфиг проверяется (`httpd -t`), ошибка — откат к прежнему.
- Чужие сайты IIS и чужой Apache (XAMPP и т. п.) агент не трогает; уже подключённые базы при обновлении остаются на IIS.
- Ручной выбор веб-сервера для поддержки: «Настройки…» → «Сервис» → «Веб-сервер» (Авто / IIS / свой Apache) или `bilem-agent setup … --web iis|apache`.
- Диагностика и отчёт для поддержки показывают службу своего Apache, порт, его конфиг и журнал ошибок.
- При удалении базы с Apache снимаются права на её папку; при удалении последней такой базы и при удалении агента служба `BilemApache` и папка `C:\ProgramData\BilemApache` убираются.
- Установщик стал больше (~58 МБ): в нём Apache для 64 и 32 бит и Visual C++.

## [0.3.0-beta.11] — 2026-10-20

- **Пароль настроек** («Настройки…» → «Сервис» → «Защита настроек», сразу под «Обновлениями»): дополнительный короткий пароль поверх прав администратора Windows — для серверов, где работают несколько администраторов. Спрашивается при входе в настройки и при копировании адреса MCP; окно в трее и перезапуск MCP — без пароля. Хранится только стойкий хеш; после 5 неверных попыток — пауза минуту. Вход в настройки, неверные попытки, задание и снятие пароля пишутся в журнал с учётной записью Windows. Забыли пароль — администратор компьютера снимает его командой `bilem-agent reset-settings-password`.
- Отчёт для поддержки больше не содержит зашифрованный пароль почты и хеш пароля настроек.

## [0.3.0-beta.10] — 2026-10-19

- **Служба Windows «Bilem Agent»:** MCP-сервер работает сам после перезагрузки — без входа на сервер и без окна. Автоматический (отложенный) запуск, LocalSystem, при сбое — перезапуск через минуту. При обновлении служба останавливается и запускается снова.
- **Окно без прав администратора:** запускается при входе любого пользователя и живёт в трее; показывает состояние службы и MCP, проверки баз, журнал службы. Права администратора (UAC) — только по кнопкам со щитом: «Настройки…», «Скопировать адрес MCP», «Перезапустить MCP», «Запустить службу».
- **Папка документов** — общая, по умолчанию C:\ProgramData\Bilem\Документы\<база>\…: у службы нет «Документов» пользователя. Папку можно сменить в «Печатных формах» → «Общее». Ранее сохранённые PDF остаются в «Документах» пользователя.
- Настройки и токен MCP читают только администраторы и служба (папка C:\ProgramData\Bilem закрыта для обычных пользователей).

- **«Кто нам должен» (receivables) и «кому должны мы» (payables).** Долг по контрагентам и договорам на дату — сальдо 1210 минус авансы 3510 (кредиторка: 3310 минус 1710), как в оборотно-сальдовой ведомости. По каким документам: номер, дата, сумма, оплачено, остаток, счёт-фактура, сколько дней. Возраст — FIFO, корзины 0–30 / 31–60 / 61–90 / 90+. Отборы: «больше N дней», «не оплатили с прошлого месяца», один контрагент, минимальная сумма, организация. Дата данных и давность выписок — в каждом ответе. ИИН контрагентов-физлиц не показывается.
- Из состава OData для БП КЗ убраны объекты российской бухгалтерии («Хозрасчетный» и др.) — при подключении базы больше нет строк «нет в конфигурации».
- Повторная настройка базы на новом компьютере больше не называет «лишними» роли bilem для служебных данных.

## [0.3.0-beta.9] — 2026-10-19

- **Подпись Microsoft (Authenticode):** MSI, bilem-agent.exe, bilem-agent.com и помощники COM подписаны сертификатом SKP.KZ LLC — Windows и SmartScreen показывают издателя.
- Обновление кнопкой проверяет издателя подписи точно по имени сертификата (без учёта регистра): чужое имя, даже похожее, — отказ.
- Из меню значка в трее убран тумблер «SMTP-клиент включён» — он только на вкладке «SMTP».
- Строка состояния — только чёрный текст: без оранжевого, зелёного и красного, ошибки тоже чёрным (решение Славы: инженерное приложение).

## [0.3.0-beta.8] — 2026-10-19

- **Строка состояния внизу окна** показывает, что с MCP: «MCP работает», «MCP запускается… ждём, пока освободится порт (6 из 30 с)», «Ошибка запуска MCP: … — нажмите «Запустить» на вкладке «MCP»», «Устанавливаю обновление … — агент закроется и запустится снова», «MCP остановлен».
- **Меню значка в трее:** «Остановить MCP» / «Запустить MCP» и «Перезапустить MCP».

## [0.3.0-beta.7] — 2026-10-19

- **MCP после обновления — причина найдена и исправлена:** порт 8796 держал помощник установки, который унаследовал сокет MCP от прежнего агента. Теперь сокет MCP не наследуется, а помощник запускается через оболочку, без наследования дескрипторов. Новая версия сразу занимает порт.
- Строка «MCP: баз подключено…» больше не повторяется при каждой попытке запуска.

## [0.3.0-beta.6] — 2026-10-19

- **Полоса прогресса** при скачивании обновления: «Скачиваю 0.3.0-beta.6: 3,2 из 9,2 МБ», затем «Устанавливаю… агент закроется и запустится снова».
- **После «Обновить» MCP поднимается сам:** если порт 8796 ещё держит прежний процесс, агент молча ждёт (до 30 с, в трее — «подключение») и запускает MCP, как только порт освободится. Ошибка — только если порт так и не освободился. В beta.5 на сервере после обновления MCP оставался остановлен с ошибкой «порт занят».

## [0.3.0-beta.5] — 2026-10-19

**Требования: Windows 10 / Server 2012 R2+, .NET Framework 4.8 (установщик предложит поставить).** Бета без подписи Microsoft: SmartScreen — «Подробнее → Выполнить в любом случае»; на Windows Server файл, скачанный браузером, — «Свойства → Разблокировать».

- **COM-коннектор 1С — только с вашего согласия.** Если в системе уже зарегистрирован коннектор другой версии платформы (им могут пользоваться обмены и обработки), агент спрашивает перед перерегистрацией; прежняя регистрация запоминается и возвращается при удалении базы или Bilem Agent. В командной строке — флаг `--allow-com-register`, команда `restore-com`.
- **Пул IIS публикации загружает профиль учётки** (loadUserProfile=true). Без профиля модуль веб-сервера 1С на Windows Server 2016 (контроллер домена) падал на первом запросе — «HTTP 0» на шаге проверки. В «Диагностике» — строка «Профиль учётки пула загружается».
- В «Диагностике» отсутствие веб-модулей у платформ, которые не публикуют базы, — справочно, а не красным.
- **Пул IIS публикации — «Без управляемого кода»** (.NET в пуле не загружается): модулю 1С он не нужен, а чужие модули ASP.NET с уровня машины больше не попадают в процесс с 1С. В «Диагностике» — строка «Пул без управляемого кода».
- **Контроллер домена:** до установки IIS агент предупреждает, что Microsoft не рекомендует ставить IIS на контроллер домена, и спрашивает, продолжать ли (`--allow-dc`).
- **Понятная причина вместо «HTTP 0»:** если при проверке публикации падает рабочий процесс IIS, агент читает журнал событий Windows и пишет, какой модуль упал (например, модуль веб-сервера 1С `wsisapi.dll`), с кодом и временем. Падения за сутки — в «Диагностике» и отчёте для поддержки.
- Фоновая проверка базы не повторяет запрос каждые 5 минут, если публикация роняет IIS (пауза на час; «Проверить» — сразу).
- Помощник COM больше не падает при выходе (запись `0xc0000409` в журнале событий после каждого подключения к базе).
- Мастер установки: в конце без строки про автономный установщик .NET.
- Строка о правах пула IIS на папку базы — в журнале настройки; при удалении базы — строка о снятии прав.

## [0.3.0-beta.4] — 2026-10-19

**Требования: Windows 10 / Server 2012 R2+, .NET Framework 4.8 (установщик предложит поставить).** Бета без подписи Microsoft: SmartScreen — «Подробнее → Выполнить в любом случае»; на Windows Server файл, скачанный браузером, — «Свойства → Разблокировать».

- **Вопрос про .NET — первым экраном** установщика, до копирования файлов: «Не найден необходимый компонент… Установить / Отмена».
- **«Готово» запускает установщик .NET через оболочку Windows** (с запросом прав). В beta.2 на сервере без .NET по «Готово» ничего не открывалось.
- **Агент сам проверяет .NET при запуске**: запускается на любом .NET 4.x и вместо системной ошибки Windows показывает своё окно «Не найден необходимый компонент» → «Установить» (веб-установщик Microsoft) / «Закрыть».
- В «Программах и компонентах» у записи — значок агента.
- Новые картинки мастера установки.

## [0.3.0-beta.2] — 2026-10-18

**Требования: Windows 10 / Server 2012 R2+, .NET Framework 4.8 (установщик предложит поставить).** Бета без подписи Microsoft: SmartScreen — «Подробнее → Выполнить в любом случае»; на Windows Server файл, скачанный браузером, — «Свойства → Разблокировать».

- **Установщик сам проверяет .NET Framework 4.8.** Нет его — мастер предлагает поставить («Установить» / «Отмена»), ставит Bilem Agent и по «Готово» запускает web-установщик Microsoft; после установки .NET (и перезагрузки, если попросит) агент запускается с ярлыка. Тихая установка без .NET — отказ с понятной строкой в журнале установщика.
- **Мастер установки** по-русски; в конце — «Запустить Bilem Agent».
- **Без пустого чёрного окна**: `bilem-agent.exe` — окно без консоли; командная строка — `bilem-agent.com` (команды `bilem-agent …` в cmd и PowerShell работают как раньше).
- **Исправлено:** на новой установке окно (или `bilem-agent serve`) и команда `bilem-agent url`, запущенные одновременно, могли выпустить разные токены MCP — первые запросы получали 401. Токен теперь выпускается один на компьютер.
- Обновление с 0.3.0-beta.1 — «Сервис» → «Обновления» (с галочкой «Получать бета-версии»).

## [0.3.0-beta.1] — 2026-10-18

Первая публичная бета.

> **Установка без подписи Microsoft.** Сертификат оформляется, поэтому Windows может предупредить: в окне SmartScreen «Windows защитила ваш компьютер» нажмите **«Подробнее» → «Выполнить в любом случае»**. На Windows Server файл, скачанный браузером, сначала разблокируйте: правой кнопкой → **«Свойства» → «Разблокировать»** (или `Unblock-File .\BilemAgent-0.3.0-beta.1.msi` в PowerShell). Подлинность — по `SHA256SUMS` и подписи `SHA256SUMS.sig` в этом релизе.

- **Установщик MSI**: «Program Files\Bilem Agent», ярлыки, обновление и откат поверх; данные `C:\ProgramData\Bilem` при обновлении и удалении сохраняются.
- **Обновления** на вкладке «Сервис»: проверка на GitHub раз в сутки, «Обновить» с проверкой подписи Ed25519 и хеша, «Откатить», канал бета-версий.
- **Печатные формы**: счёт на оплату, доверенность (форма Д-1), акт сверки взаимных расчётов — PDF с логотипом, печатью и подписью; настройки по формам, «Пробный документ…».
- **Почта (SMTP)**: отправка счёта, акта сверки и доверенности из чата; доверенности — только на «Список адресов для отправки доверенностей».
- **«Данные на …»**: ответы с цифрами называют дату последней выписки по каждому счёту и предупреждают о давности.
- **Журнал аудита** печати и отправки: кто запросил (программа, адрес, пользователь Tailscale), хеш PDF, без содержимого.
- **Доступ**: дерево разделов из подсистем 1С, чтение и запись по объектам; персональные данные закрыты.
