# Онбординг: подключение базы 1С к Bilem Agent

Bilem Agent читает данные 1С через стандартный интерфейс OData. Публикация базы открыта только для этой машины (127.0.0.1 и ::1), расширение в базу не ставится. Ниже — что делает прототип `spike/setup-spike.ps1` на каждом шаге. Всё, что пройдёт в скрипте, переносится в программу.

Без `-Apply` скрипт только проверяет и пишет план — ничего не меняет. Журнал каждого запуска — `C:\ProgramData\Bilem\spike\setup-<дата-время>.log`.

## Шаг 0. Права администратора Windows

Нужен PowerShell «от имени администратора»: регистрация COM, IIS, права на папку базы. Без них — остановка с подсказкой.

## Шаг 1. База

Папка с файлом `1Cv8.1CD` (файловая база; серверные — следующий этап). Имя публикации по умолчанию — `bilem_<имя папки>`.

## Шаг 2. Платформа 1С и разрядность

Ищет установленные платформы 8.3 с `comcntr.dll` в `Program Files` и `Program Files (x86)`, берёт самую новую (или `-PlatformVersion`). COM-коннектор работает только в процессе той же разрядности, поэтому при несовпадении скрипт один раз перезапускается в PowerShell нужной разрядности.

Затем проверяет COM-коннектор `V83.COMConnector`: ProgID, путь к `comcntr.dll` выбранной платформы, библиотеку типов. С `-Apply` при необходимости регистрирует `comcntr.dll` (`regsvr32`).

## Шаг 3. Вход в базу

По COM под администратором 1С. Логин — окном или `-AdminUser`, пароль — окном, `-AdminPassword` (учебная база) или переменной окружения `BILEM_1C_ADMIN_PWD`. База без пользователей — `-NoAuth`. Пароль администратора нигде не сохраняется.

Типовые отказы с подсказкой: неверный логин/пароль, база в монопольном режиме, базе нужно обновление, нет свободной лицензии.

## Шаг 5. Конфигурация

Имя, синоним и версия конфигурации; есть ли БСП (справочник «Пользователи»). `-ListRoles` — вывести роли конфигурации и выйти (чтобы выбрать права для `bilem`).

## Шаг 6. Пользователь bilem

Создаёт или обновляет пользователя ИБ `bilem`: вход по паролю 1С, без входа через Windows, не в списке выбора, роли из `-Roles`. Пароль — 24 случайных символа, хранится только в DPAPI-файле `C:\ProgramData\Bilem\spike\<публикация>.bilem.cred` (расшифровать может только та же учётная запись Windows на этой машине). Если в конфигурации есть БСП — создаёт элемент справочника «Пользователи», связанный с пользователем ИБ.

Роли по умолчанию — **только чтение** (для БП КЗ 3.0): `БазовыеПраваБСП`, `БазовыеПраваБК`, `ЧтениеДанныхБухгалтерии`, `ЧтениеКурсовВалют`, `ЧтениеЧековККМ`, `ЧтениеОтчетаОРозничныхПродажах`. Почему именно они и как проверено — [rights.md](rights.md). Если `bilem` уже есть, шаг пишет его текущие роли и отличия от заданных.

## Шаг 7. Состав стандартного интерфейса OData

Добавляет в состав OData объекты из `-ODataObjects`, которых там ещё нет: справочники (организации, контрагенты, договоры, номенклатура, склады, кассы, банковские счета и т. п.), документы по деньгам (платёжные поручения и ордера, кассовые ордера, оплаты картой), продажам, покупкам, складу и расчётам с контрагентами, регистр бухгалтерии и план счетов, курсы валют и цены номенклатуры. Зарплата, кадры и физлица (в том числе авансовые отчёты и контактные лица) в состав не входят. Объекты, которых нет в конфигурации, пропускает — список общий для разных конфигураций.

Что из этого видит ИИ, ограничивает слой MCP Bilem Agent; публикация OData доступна только с этой машины.

Затем под администратором проверяет, в каких объектах состава есть записи (только признак «есть / нет»), — для проверки чтения на шаге 10.

## Шаг 8. Веб-сервер IIS

Проверяет, что IIS установлен. Если нет — с `-Apply -EnableIIS` включает компоненты Windows (веб-сервер, ISAPI, «Ограничения по IP», консоль) через `dism`.

## Шаг 9. Публикация (только 127.0.0.1)

- `webinst` публикует базу в `C:\inetpub\wwwroot\<публикация>`;
- в `default.vrd` включает OData и пул сессий;
- пул IIS `Bilem1C` нужной разрядности;
- анонимный вход публикации — от имени удостоверения пула, а не `IUSR`;
- права на изменение папки базы — только пулу `Bilem1C`;
- «Ограничения по IP»: всё запрещено, кроме 127.0.0.1 и ::1 (компонент ставится с `-EnableIIS`, если его нет);
- перезапуск пула `Bilem1C`.

## Шаг 10. Проверка

С этой машины под `bilem`:

- `$metadata` OData — 200 (иначе — код HTTP с подсказкой: 401 — пользователь, 403 — ограничение по IP, 404 — публикация, 500 — ошибка 1С);
- **чтение:** каждый объект состава — 200, и не пусто там, где в базе есть записи;
- **запись запрещена:** `POST` документа и `PATCH` справочника — отказ 1С, в базе ничего не создано и не изменено;
- **периметр:** без пароля — 401, по адресам машины (не 127.0.0.1) — 403.

В журнал — только коды ответов и счётчики, без данных. Любая проверка не прошла — FAIL и код выхода 1; все прошли — «ГОТОВО» с адресом OData и описание базы для MCP-сервера `C:\ProgramData\Bilem\spike\<публикация>.base.json`: короткое имя, адрес OData, пользователь, путь к DPAPI-файлу, конфигурация и версия (OData их не отдаёт). Пароля в описании нет.

`-Verify` — те же проверки и текущие роли `bilem` для уже подключённой базы, без изменений (например, после входа администратора, чтобы убедиться, что роли не слетели).

## Что скрипт меняет на машине

- регистрация `comcntr.dll` выбранной платформы (если нужно);
- компоненты Windows IIS (только с `-EnableIIS`);
- публикация `C:\inetpub\wwwroot\<публикация>`, пул IIS `Bilem1C`, ограничение по IP для этой публикации;
- права пула `Bilem1C` на папку базы;
- в базе: пользователь `bilem` (и элемент справочника «Пользователи»), состав интерфейса OData;
- файлы в `C:\ProgramData\Bilem\spike\`: журналы, DPAPI-файл пароля `bilem`, описание базы для MCP (`*.base.json`).

Известные проблемы и что скрипт с ними делает — [known-issues.md](known-issues.md).
