# Права пользователя bilem

У пользователя `bilem`, под которым Bilem Agent читает 1С, — **только чтение. Запись запрещена самой 1С, и это проверяется при каждом подключении.**

Периметр (публикация только на 127.0.0.1) и слой MCP — это «дверь». Роли `bilem` — «сейф» внутри 1С: даже если по ошибке придёт запрос на создание, изменение, проведение или удаление, 1С ответит «Нарушение прав доступа».

## Какие роли

По умолчанию для «Бухгалтерии для Казахстана» 3.0 (параметр `-Roles`; роли, которых нет в конфигурации, пропускаются с предупреждением):

| Роль | Зачем |
| --- | --- |
| `БазовыеПраваБСП` | вход и служебные данные БСП (без неё сеанс не открывается) |
| `БазовыеПраваБК` | базовые права конфигурации |
| `ЧтениеДанныхБухгалтерии` | чтение справочников, документов, регистра бухгалтерии и плана счетов из состава OData |
| `ЧтениеКурсовВалют` | валюты и курсы валют |
| `ЧтениеЧековККМ` | чеки ККМ |
| `ЧтениеОтчетаОРозничныхПродажах` | отчёты о розничных продажах |

Нет ни одной роли «Добавление и изменение…», административной («Полные права», «Администрирование», «Администратор системы») или зарплатно-кадровой.

### Как подобрано

Для каждого объекта из состава OData проверено (`ПравоДоступа("Чтение", …)`), какие роли «Чтение…» и «Базовые…» дают его чтение. `ЧтениеДанныхБухгалтерии` покрывает почти весь состав; часть объектов (кассовые и платёжные ордера, перемещение и списание товаров, акт сверки и др.) читается только ею. Курсы валют, чеки ККМ и отчёты о розничных продажах — отдельными ролями.

Для выбранных ролей проверены права «Добавление», «Изменение», «Удаление», «Проведение» на все объекты конфигурации. На объекты учёта таких прав нет. Есть служебные права БСП: изменение своей записи в справочнике «Пользователи» и сохранение пользовательских настроек отчётов.

`ЧтениеДанныхБухгалтерии` даёт и чтение части объектов вне состава OData (в том числе связанных с зарплатой: ввод начальных остатков по зарплате, авансовые отчёты, сведения о выплатах). Через OData они не видны: в состав не входят.

## Как проверено

Шаг 10 скрипта при каждом подключении (и в режиме `-Verify`):

1. **Чтение работает.** Каждый объект из состава — HTTP 200. Под администратором по COM заранее проверяется, в каких объектах есть записи; если записи есть, а `bilem` получил пустой ответ — ошибка («не видит»). В журнал пишутся только коды ответов и счётчики, данные — нет.
2. **Запись запрещена.**
   - `POST` нового документа «Счёт на оплату покупателю» — отказ 1С (HTTP 500 «Нарушение прав доступа!»), число документов до и после одинаковое;
   - `PATCH` элемента справочника «Контрагенты» (тем же наименованием — даже при разрешённой записи данные не поменялись бы) — отказ 1С, версия данных не изменилась.

   Если 1С запись приняла — ошибка «ЗАПИСЬ РАЗРЕШЕНА» и код выхода 1. Проверено обратным прогоном с ролью «Полные права»: проверка ловит и создание документа, и изменение справочника.
3. **Периметр.** Без пароля — 401; по адресам машины (не 127.0.0.1) — 403.

### Роли не слетают

Проверено: после подключения в базу вошёл администратор через 1С:Предприятие (тонкий клиент, 3 минуты; отработали обработчики БСП при входе и регламентные задания), затем `-Verify` — роли `bilem` те же, чтение работает, запись запрещена.

## Вкладка «Доступ» (v0.2)

- **Чтение снято** — объект сразу не виден инструментам MCP, после «Применить» с паролем администратора — убран из состава OData (проверка: выключенных наборов в `$metadata` нет).
- **Чтение поставлено** для объекта вне состава по умолчанию — добавляется в состав OData; если ролей профиля не хватает — роль чтения с самым узким правом (меньше всего объектов с добавлением).
- **Запись поставлена** — роль «ДобавлениеИзменение…» с самым узким правом по `ПравоДоступа` (для «Счёта на оплату покупателю» в БП КЗ 3.0 — `ДобавлениеИзменениеСчетовПокупателям`, запись на один объект). Роли с «Полными правами», администрированием и устаревшие («Удалить…») не выбираются никогда.
- **Запись снята** — роль убирается, если больше ни для чего не нужна; проверка снова «запись запрещена».
- Запрет записи после «Применить» проверяется на объектах, где запись выключена (POST документа и PATCH справочника — отказ 1С).
- Типовые роли записи часто включают и право проведения — поэтому запрет держит программа: вызовов проведения, отмены проведения и удаления в коде нет (это проверяет тест).
- Повторная настройка базы не сбрасывает выбранный доступ.

## Ограничение доступа на уровне записей

В проверенной базе ограничение доступа на уровне записей (БСП) **выключено**, поэтому ролей пользователю напрямую достаточно. Если в базе клиента оно включено, роли «Чтение…» без групп доступа могут давать пустые ответы — шаг 10 это поймает («не видит»). Тогда — путь через БСП: профиль групп доступа «Bilem» с теми же ролями, группа доступа «Bilem» со всеми организациями, `bilem` — участник группы. В скрипте пока не реализовано.
