# Известные проблемы онбординга

Справочник для `spike/setup-spike.ps1`: признак → причина → что делает скрипт. Каждая проблема, найденная на прогоне, попадает сюда и в скрипт.

## 1. Скрипт бесконечно перезапускает сам себя

- **Признак:** в журнале раз в секунду «Платформа 32-бит, а PowerShell 64-бит — перезапускаюсь…», затем «Платформа 64-бит, а PowerShell 32-бит…»; в `C:\ProgramData\Bilem\spike\` растёт число журналов.
- **Причина:** в 32-битном PowerShell переменная `ProgramFiles` указывает на `C:\Program Files (x86)`. 32-битная платформа 1С из этой папки принималась за 64-битную, и скрипт перезапускался в 64-битный PowerShell, а оттуда — снова в 32-битный.
- **Что делает скрипт:** 64-битную папку берёт из `ProgramW6432`, 32-битную — из `ProgramFiles(x86)`. Перезапуск в PowerShell нужной разрядности — только один раз (флаг в переменной окружения); если и после него разрядность не совпала — ошибка с подсказкой, а не петля.

## 2. TYPE_E_LIBNOTREGISTERED при подключении к базе

- **Признак:** «Не удалось подключиться: Library not registered. (Exception from HRESULT: 0x8002801D)».
- **Причина:** COM-коннектор `V83.COMConnector` зарегистрирован (ProgID и класс есть), а его библиотека типов (TypeLib) — нет. Проверка только ProgID этого не видит.
- **Что делает скрипт:** проверяет ProgID, путь к `comcntr.dll` выбранной платформы и TypeLib. Чего-то нет — в диагностике пишет план, с `-Apply` регистрирует `comcntr.dll` через `regsvr32` и проверяет ещё раз.

## 3. Пустые свойства объектов 1С по COM

- **Признак:** «Конфигурация:  () версии» с пустыми значениями, затем «You cannot call a method on a null-valued expression»; методы вроде `Find`/`Count` «не найдены».
- **Причина:** PowerShell не видит свойства объектов 1С при прямом обращении (`$c.Metadata` — `$null`). Кроме того, коллекции 1С (роли, справочники, роли пользователя) перечислимы, и PowerShell разворачивает их в массив, когда функция их возвращает; пустая коллекция превращается в `$null`.
- **Что делает скрипт:** свойства читает и пишет через `InvokeMember` (функции `P` и `SetP`), результат возвращает без разворачивания (`return ,…`); методы объектов 1С вызывает напрямую.

## 4. Скрипт упал, а код выхода 0

- **Признак:** журнал обрывается на середине шага, без строки FAIL; вызывающая программа видит код 0.
- **Причина:** непредвиденное исключение в дочернем PowerShell (после перезапуска под нужную разрядность) не превращалось в ненулевой код выхода.
- **Что делает скрипт:** общий перехватчик (`trap`) пишет любую непредвиденную ошибку в журнал как FAIL с номером строки и завершает работу с кодом 1.

## 5. Ошибка TypeData при шифровании пароля

- **Признак:** «Error in TypeData "System.Security.AccessControl.ObjectSecurity": The member … is already present» на шаге 6.
- **Причина:** скрипт запущен из PowerShell 7. Windows PowerShell 5.1 унаследовал его `PSModulePath` и загрузил модули PowerShell 7 (`Microsoft.PowerShell.Security`), несовместимые с 5.1.
- **Что делает скрипт:** в Windows PowerShell 5.1 оставляет в `PSModulePath` только пути `WindowsPowerShell`. Пароль `bilem` шифруется в DPAPI до записи пользователя — если шифрование упадёт, пароль в базе не сменится впустую.

## 6. Install-WindowsFeature не найден

- **Признак:** «The term 'Install-WindowsFeature' is not recognized…» при установке IIS или «Ограничений по IP».
- **Причина:** при 32-битной платформе 1С скрипт работает в 32-битном PowerShell, а модуля ServerManager (и `Enable-WindowsOptionalFeature` в нужном виде) там нет.
- **Что делает скрипт:** компоненты Windows ставит через 64-битный `dism.exe` (из 32-битного процесса — через `Sysnative`); имена компонентов `IIS-*` одинаковы на сервере и клиентской Windows. `appcmd.exe` и проверка `iprestr.dll` — тоже через `Sysnative`.

## 7. HTTP 500 «Ошибка режима доступа к файлу базы данных»

- **Признак:** проверка OData на шаге 10 — HTTP 500, в ответе «Ошибка режима доступа к файлу базы данных '…\1Cv8.1CD'».
- **Причина:** по умолчанию анонимный вход в IIS идёт от имени `IUSR`, и модуль 1С открывает файлы базы от его имени, а права на папку были только у пула (`IIS APPPOOL\…`) и `IIS_IUSRS`.
- **Что делает скрипт:** переводит анонимный вход публикации на удостоверение пула (`anonymousAuthentication userName=""`) и даёт права на изменение папки базы только пулу `Bilem1C`. `IUSR` и `IIS_IUSRS` прав на базу не получают.

## 8. «Object reference not set to an instance of an object» при запросе по COM

- **Признак:** на шаге 7 у каждого объекта «не удалось проверить наличие записей: … Object reference not set to an instance of an object».
- **Причина:** две сразу. Прямой вызов `$query.Execute()` из PowerShell при ошибке 1С возвращает пустой объект, и настоящий текст ошибки теряется. А ошибка была в тексте запроса: псевдоним `Есть` — зарезервированное слово языка запросов 1С (`ЕСТЬ NULL`).
- **Что делает скрипт:** методы, которые могут вернуть ошибку 1С, вызывает через `InvokeMember` (функция `M`) — текст ошибки 1С попадает в журнал; псевдоним в запросе — не зарезервированное слово. Если проверка наличия записей не удалась, объект всё равно проверяется на чтение по коду ответа.

## 9. Отказ в записи через OData — HTTP 500, а не 403

- **Признак:** `POST`/`PATCH` под пользователем только с ролями чтения возвращают HTTP 500 с текстом «Нарушение прав доступа!».
- **Причина:** так 1С отвечает в стандартном интерфейсе OData на нехватку прав; 403 там не используется.
- **Что делает скрипт:** запрет записи определяет не по коду, а по результату: ответ не 2xx **и** в базе ничего не появилось (число документов до и после) и не изменилось (версия данных элемента). Текст ошибки 1С пишет в журнал.

## 10. Остатки регистра бухгалтерии с условием по счетам — HTML вместо JSON

- **Признак:** запрос `AccountingRegister_…/Balance(Period=…, AccountCondition='Account_Key eq guid''…'' or …')` с несколькими счетами возвращает HTML-страницу ошибки IIS, а не ответ 1С; с одним счётом — работает.
- **Причина:** параметры функции `Balance` стоят в сегменте пути URL, а у http.sys лимит длины сегмента — 260 символов; десяток GUID его превышает.
- **Что делает MCP-сервер:** условие по счетам передаёт в `$filter` (строка запроса, лимита сегмента нет): `Balance(Period=datetime'…')?$filter=Account_Key eq guid'…' or …`. Время ответа — десятки миллисекунд.

## 11. appcmd находит «приложение», которого нет

- **Признак:** проверка «публикация уже есть» срабатывает для новой базы; удаление может затронуть не то приложение.
- **Причина:** `appcmd list app "Default Web Site/<имя>"` для несуществующего приложения возвращает корневое приложение сайта (`Default Web Site/`) с кодом 0.
- **Что делает программа:** приложение и пул ищет по точной строке в полном списке (`APP "Default Web Site/<имя>"`, `APPPOOL "<имя>"`).

## 12. Повторный setup падал на «List<string> не содержит определения Except»

- **Признак:** первый `setup` проходит, повторный — ошибка помощника COM в `ensureUser`.
- **Причина:** в помощнике COM результат вызова метода с `dynamic`-аргументами — тоже `dynamic`, а у `dynamic` нет методов-расширений LINQ. При первом запуске сравнение ролей до `Except` не доходило.
- **Что делает программа:** тип таких переменных указан явно.

## 13. HttpListener слушал бы все адреса машины

- **Признак:** (предотвращено до появления) MCP, поднятый на `http://127.0.0.1:<порт>/` через `HttpListener`, принимает соединения и на других адресах машины — http.sys по умолчанию слушает все IP и сверяет только заголовок Host.
- **Что делает программа:** MCP-сервер — на `TcpListener(127.0.0.1)`; с другого адреса соединение не устанавливается вовсе. Проверяется юнит-тестом.

## 14. Пробел в $filter как «+» — HTTP 400

- **Признак:** поиск по фразе из нескольких слов (`substringof('Мост отряд', Description)`) отвечает HTTP 400, по одному слову — работает.
- **Причина:** 1С не декодирует `+` как пробел внутри `$filter` (так кодируют формы HTML и некоторые библиотеки).
- **Что делает программа:** строка запроса — через `Uri.EscapeDataString`, пробел — `%20`. Проверено на стенде: `%20` — 200, `+` — 400; закреплено тестом.

## Не ошибка: кириллица в curl из Git Bash

При ручной проверке MCP или OData через `curl -d '…'` в Git Bash на Windows кириллица в аргументах командной строки передаётся не в UTF-8 — поиск по русскому слову «ничего не находит». Тело запроса — из UTF-8 файла: `curl --data-binary @request.json`.

## Не ошибка: объектов нет в конфигурации

Список `-ODataObjects` по умолчанию рассчитан на разные конфигурации. В «Бухгалтерии для Казахстана» 3.0 нет документов «Поступление на расчётный счёт» и «Списание с расчётного счёта», регистра бухгалтерии и плана счетов «Хозрасчетный» (там — «Типовой»). Скрипт пишет «нет в конфигурации» и пропускает их.
